## 2. ★ 核心结论：拦截失效的真实原因

### 2.1 原拦截器为什么永远不工作

`Core/Helpers/SystemCalendarInterceptor.cs` 的逻辑是：监听全局窗口事件（`SetWinEventHook(EVENT_OBJECT_SHOW, EVENT_MAX)`），
匹配**进程名 `ShellExperienceHost`** + **类名 `Windows.UI.Core.CoreWindow`** + 右下角贴合（容差 50px）+ 尺寸 >200×100。

**实测证明这条链路在本机根本不存在：**

1. **点时钟后什么都不弹。** 全屏截图对比：点击前后整屏差异 bbox=(337,1209,1774,2052)，只是输入法候选框消失，
   **没有任何新窗口出现，没有日历面板**。
2. **窗口枚举证据**：`ShellHost.exe` 与 `explorer.exe` 持有的 `Windows.UI.Core.CoreWindow` / `Microsoft.UI.Content.PopupWindowSiteBridge`
   窗口尺寸恒为 **1×1**（`DesktopWindowXamlSource`），是常驻宿主模板，**不满足拦截器的尺寸判据**。
3. **因果链**：ExplorerPatcher 用 Win10 风格任务栏 → 时钟是旧式 `TrayClockWClass` → 与 24H2 的日历宿主链路已断 →
   点击不产生任何弹窗 → 拦截器永远等不到目标。

### 2.2 诊断过程中排除的干扰项

- `IsWindowVisible()` 对 WinUI 弹窗**恒返回 True**（靠 DWM 遮蔽 cloak/uncloak 切换），
  所以用可见性变化抓弹窗**从判据上就是错的**。已用 `DWMWA_CLOAKED(14)` 重测，仍未捕捉到日历弹窗，进一步佐证 §2.1。
- 不要再用「可见性变化」作为检测手段。

### 2.3 结论：不需要「拦截」，需要「接管点击」

因为点时钟**本就不弹任何东西**，所以：

- ❌ 「修正拦截器兼容 24H2」是**修一个不存在的东西**，无意义。
- ✅ 正确做法：**用低级鼠标钩子直接识别「用户点了时钟」这件事，然后弹出我们自己的面板**。

这比拦截更干净：**无闪烁、无竞态、不依赖脆弱的窗口特征匹配、不依赖系统版本。**

## 3. ★ 可行性已用 POC 实测验证

多轮实测（含对照实验）得到确定结论：

| 验证项 | 结果 |
|--------|------|
| `SetWindowsHookExW(WH_MOUSE_LL=14, ...)` 注册 | ✅ 成功（返回非 0 句柄） |
| 钩子能否捕获鼠标事件 | ✅ 捕获到 DOWN/UP 各 2 次 |
| **能否精确命中时钟** | ✅ 命中的窗口句柄 = `0x1019e`（正是 `TrayClockWClass`） |
| 对照组：点任务栏中间（非时钟） | ✅ 正确判定为「未命中」 |

**钩子回调拿到的是物理像素坐标**（实测点中时钟中心 (3702,2130)），
`GetWindowRect` 在 DPI 感知进程下同样返回物理像素 —— 两者**坐标系一致，可直接比较**。

### 3.1 实测踩到的坑（务必规避）

1. **DPI 感知必须设置**：未设置时 `GetSystemMetrics(0)` 返回 2560×1440（缩放后值），
   时钟坐标被算到 (2468,1420)，点击落空。设置 `SetProcessDpiAwareness(2)`（或清单声明 PerMonitorV2）后
   得到真实 3840×2160，时钟坐标 (3702,2130)，点击生效。
   → **WPF 应用需确保清单声明 DPI 感知，否则勾子坐标与窗口矩形不在同一坐标系。**
2. **`CallNextHookEx` 必须显式声明签名**：64 位下 `LPARAM` 会溢出报
   `OverflowError: int too long to convert`，导致回调静默失效、读到陈旧坐标。必须设 `argtypes`。
3. **钩子需要消息循环**才能收到回调（WPF 有 Dispatcher 循环，可直接用）。
4. Windows 上 `SendInput` 模拟点击**是有效的**（已用「开始按钮」对照验证：开始菜单正常弹出）。

## 7. 本次改造范围（建议）

1. **入口改造**：新增基于 `WH_MOUSE_LL` 的时钟点击接管；移除/停用失效的 `SystemCalendarInterceptor`；
   托盘图标默认隐藏 + 设置项可开启；提供快捷键兜底。
2. **数据源诚实化**：设置里「系统日历」选项要么明确标注不可用、要么改为明确的模拟数据开关；
   **绝不静默返回假数据**。保留 ICS 订阅（节假日/放假安排走 ICS）。
3. **日期工具增强**：新增二十四节气计算与显示；农历/节气/节日的显示优先级与样式。
4. **界面重做（日期工具向）**：月历为主体并放大；面板支持**拖拽自由缩放**并记忆尺寸；
   日程区保留但弱化（可折叠/默认收起）。
5. **一致性清理**：命名统一 WinCal、数据目录统一 `%LOCALAPPDATA%\WinCal`、清理死设置、
   修正周起始日默认值不一致。

## 8. 给团队的技术约束（硬性）

- 技术栈不变：`.NET 8` + `WPF` + `MVVM`（`CommunityToolkit.Mvvm`），纯 WPF 矢量渲染，不引入 UI 框架。
- 构建环境：dotnet SDK 在 `C:\Users\darkangellxc\AppData\Local\Microsoft\dotnet\dotnet.exe`（**本机特有，勿写死 `C:\Program Files\dotnet`**）。
- 构建脚本 `build.bat` / `build_nopause.bat` / `publish.bat` 已改为自动探测 dotnet 路径，**不要改回硬编码**。
- `PublishTrimmed` 已移除（.NET 8 WPF 不支持 Trim，且会破坏 `SetWinEventHook` 回调委托），**不要加回**。
- 发布命令（已验证可用）：
  ```
  dotnet publish WinCal.csproj -c Release -r win-x64 --self-contained true ^
    -p:PublishSingleFile=true -p:EnableCompressionInSingleFile=true -o ./dist
  ```
  产物 `dist/WinCal.exe` 约 65 MB，自包含。
- 钩子实现注意 §3.1 的三个坑（DPI 感知、`CallNextHookEx` 签名、消息循环）。
- 面板自由缩放的实现难点：当前 `PopupWindow` 是 `WindowStyle=None` + `AllowsTransparency=True` +
  `SizeToContent="Height"` + `ResizeMode="NoResize"`，**`SizeToContent` 与自由缩放冲突**，需一并处理。
- 关闭面板、退出程序时必须卸载钩子（`UnhookWindowsHookEx`），避免残留影响用户鼠标。
