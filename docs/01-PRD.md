## 1. 项目信息

| 项 | 内容 |
|---|---|
| Language | 中文 |
| Programming Language | 不变：`.NET 8` + `WPF` + `MVVM`（`CommunityToolkit.Mvvm`），纯 WPF 矢量渲染，不引入第三方 UI 框架 |

### 1.1 原始需求复述

用户（郑州某公司办公人员，Windows 11 / 24H2 内核 + ExplorerPatcher 环境）对 fork 来的 WinCal 功能不满意，核心不满有两点：

> 「我让你 fork 这个项目的原因，是因为这个项目的软件功能不太让我满意」
> 「不能拦截系统日历，它现在非要在任务栏弄个小图标，这就很烦」

拆解为两个真实诉求：

1. **入口问题**：他不想为了看日历去点托盘小图标。他希望**点任务栏上的系统时钟**就直接弹面板。
   原项目做的是「拦截系统日历并替换」——但实测证明**本机点时钟什么都不弹**，所以「拦截」这个手段从根上不成立，必须改为「**接管点击**」。
2. **内容问题**：他要的是**日期工具**（农历、节气、节假日、放假安排、调休看得清），不是日程管理工具。原项目把 340px 宽的面板里塞了 160px 高的事件区，把最重要的月历挤没了。

---

## 2. 产品定位

**一句话**：改造后的 WinCal 是一个「**Windows 任务栏时钟的替代品**」——点任务栏时钟弹出的一块**日期信息面板**，核心价值是让办公用户一眼看清「今天是几号、农历几月几、什么节气、什么节日、这周哪几天上班哪几天休」。

**它不是什么**：不是日历客户端，不是日程管理工具，不是 To-Do。日程能力作为**可选模块保留**（默认关闭），但绝不作为产品的组织中心。

**定位对照表**：

| 维度 | 改造前（原项目） | 改造后（本 PRD） |
|---|---|---|
| 入口 | 托盘小图标（用户明确反感） | 点任务栏时钟（接管点击）；托盘图标默认隐藏 |
| 信息重心 | 近期事件列表 | 农历 / 节气 / 节假日 / 调休 |
| 月历占比 | 约 50%（被 160px 事件区挤压） | ≥ 78%（日程收起态） |
| 面板尺寸 | 固定 340px 宽，`ResizeMode=NoResize` | 默认 420×620，可自由拖拽缩放并记忆 |
| 日程 | 默认强展示 | 默认收起 / 可整体关停（功能保留） |
| 数据源 | 默认「系统日历」，实际静默返回**随机假数据** | 节假日走 ICS 订阅（实时更新），假数据彻底消除 |

## 3. 产品目标

| # | 目标 | 可量化验收指标 |
|---|---|---|
| G1 | **入口可用**：点任务栏时钟必定弹出面板 | 在实测机（3840×2160 + 150% 缩放 + ExplorerPatcher Win10 风格任务栏）上连续 20 次点击时钟，**20/20 弹出**；从鼠标 UP 到面板可见 ≤ 150ms；钩子回调内耗时 < 1ms，鼠标无可感知卡顿 |
| G2 | **信息可读**：农历/节气/节假日/调休一眼可辨 | 日期格子默认档数字字号 ≥ 18px、辅助文字 ≥ 10px；法定节假日与调休上班日**必定**有视觉区分（不是只靠事件圆点）；当月节假日可在面板内直接读出「哪天休、哪天上班」 |
| G3 | **面板可调**：尺寸由用户决定并记住 | 拖拽四边/四角自由缩放；默认 420×620、最小 320×420；关闭重开后尺寸与日程展开态**完全恢复**；缩放过程面板右下角锚点固定（始终贴住任务栏） |
| G4 | **不再骚扰**：默认无托盘图标 | 首次安装后托盘区**0 个** WinCal 图标；设置中可开启 |
| G5 | **数据诚实**：绝不给假数据 | 面板内**任何情况下**不得出现 `MockCalendarService` 的 `Random()` 事件；数据源不可用时面板显示明确横幅说明原因 |
| G6 | **功能不丢**：日程能力完整保留 | 日程列表、事件详情浮层、ICS 解析、去重、双层缓存等现有能力**代码保留且可被开关启用**，启用后行为与改造前一致 |

## 4. 用户故事

| # | 故事 |
|---|---|
| US-1 | **作为**办公用户，**我想要**直接点任务栏右下角的时间，**以便**像用系统日历一样顺手地弹出我要的日期面板，而不用去托盘里找一个小图标。 |
| US-2 | **作为**办公用户，**我想要**在面板里一眼看到这个月哪天放假、哪天需要调休上班，**以便**提前安排通勤和家庭事务，不用去搜新闻确认。 |
| US-3 | **作为**办公用户，**我想要**看到每天对应的农历和节气（尤其是清明、冬至这类），**以便**处理家里的传统事务和节气相关的安排。 |
| US-4 | **作为**办公用户，**我想要**用鼠标拖面板的边缘把它拉大，**以便**在我大屏（3840×2160）上看得更清楚；并且下次打开还是我调好的大小。 |
| US-5 | **作为**办公用户，**我想要**默认看不到托盘小图标，**以便**任务栏保持干净；如果哪天我想要图标，能在设置里打开。 |
| US-6 | **作为**不需要日程管理的用户，**我想要**把底下那坨事件列表关掉或者收起来，**以便**面板纯粹是日期工具；但**我不希望**这个功能被删掉，万一以后要用。 |
| US-7 | **作为**用户，**我想要**节假日数据来自我订阅的 ICS 链接，**以便**放假安排公布后能自动更新，而不是等软件升级。 |
| US-8 | **作为**用户，**我想要**一个键盘快捷键能弹面板，**以便**在时钟点击出问题（比如换了任务栏软件）时还有退路。 |
| US-9 | **作为**用户，**我想要**设置里如果某个数据源不能用，界面必须**明确写出来**，**以便**我不会被一堆看起来真的事件误导。 |

## 5. 需求池

> 优先级：**P0 = 必须**（不做则本次改造失败）；**P1 = 重要**（做则体验完整）；**P2 = 可选**（有余力再做）。
> 验收标准均为可实测、可复现。

### 5.1 P0 — 必须

#### P0-1 时钟点击接管（入口重做）

**需求**：用低级鼠标钩子 `SetWindowsHookExW(WH_MOUSE_LL)` 识别「用户点了任务栏时钟」，命中则弹出 WinCal 面板；**不再尝试拦截系统日历**（实测证明点时钟不弹任何东西，拦截无对象）。

**必须满足**：
- 命中判定同时支持 Win10 风格时钟（`TrayClockWClass`）与 Win11 原生时钟（XAML 任务栏下的时钟窗口/区域），两者任一命中即弹面板
- 命中失败时**不得吞掉点击**，必须 `CallNextHookEx` 放行
- 停用/移除失效的 `SystemCalendarInterceptor`（`Core/Helpers/SystemCalendarInterceptor.cs`），不得保留为默认启用路径
- 沿用 `WindowPositionHelper.PositionNearTaskbar` 定位逻辑，面板靠近所在显示器的任务栏

**验收标准**：
1. 实测机上连续点时钟 20 次 → 20 次弹出面板，0 次漏弹、0 次吞点击（点击后任务栏行为仍正常）
2. 点击任务栏**非时钟区域**（如开始按钮右侧空白、其他托盘图标）→ **0 次**误弹面板
3. 面板弹出后，鼠标立即移动到面板上无卡顿；用 Performance Monitor 观察钩子回调平均耗时 < 1ms
4. 双屏下：点主屏时钟弹在主屏右下，点副屏时钟弹在副屏右下（`MonitorFromWindow` 生效）
5. 退出程序后 `UnhookWindowsHookEx` 被调用，注册表中无残留钩子，鼠标行为恢复正常

**技术约束（引用 00 文档 §3.1，不可绕过）**：
- 进程**必须**声明 DPI 感知（PerMonitorV2 清单 或 `SetProcessDpiAwareness(2)`），否则钩子物理坐标与 `GetWindowRect` 不在同一坐标系
- `CallNextHookEx` 在 64 位下必须显式声明 `argtypes`，否则回调静默失效
- 钩子需消息循环（WPF Dispatcher 循环可直接复用）

#### P0-2 托盘图标默认隐藏

**需求**：新增设置项「显示托盘图标」，**默认关闭**。

**验收标准**：
1. 全新安装（删除 `%LOCALAPPDATA%\WinCal\settings.json`）后首次启动，Windows 通知区域**无** WinCal 图标
2. 设置中开启后，图标**立即**出现（无需重启），且图标仍为动态绘制的今日日期数字
3. 关闭后图标**立即**消失
4. 该状态写入 `settings.json`，重启后保持
5. 图标隐藏时，「退出程序」入口转移到设置窗口内（面板齿轮 → 设置 → 退出），不因无图标而无法退出

---

#### P0-3 面板自由缩放 + 尺寸记忆

**需求**：面板支持鼠标拖拽**四边 + 四角**自由缩放，尺寸持久化。

**验收标准**：
1. 鼠标移到面板四条边 → 光标变 `SizeWE`/`SizeNS`；四角 → `SizeNWS`/`SizeNES`/`SizeSW`/`SizeSE`；热区宽度 6px（角部 10×10）
2. 拖动后可缩放至最小 320×420 与最大（当前显示器工作区尺寸 − 16px）
3. 缩放过程中**右下角锚点固定**（面板始终贴着任务栏一侧，向左/上生长）
4. 缩放结束后 500ms 内写入 `settings.json`；关闭再开启面板，尺寸与缩放前一致（误差 0px）
5. 面板内容随尺寸自适应，不出现内容溢出、错位、滚动条异常
6. **必须处理**：现有 `PopupWindow` 为 `WindowStyle=None` + `AllowsTransparency=True` + `SizeToContent="Height"` + `ResizeMode="NoResize"`，`SizeToContent` 与自由缩放**硬冲突**，须一并改造（由架构师定技术方案，如 `WindowChrome.ResizeBorderThickness` + 固定 Height）

**交互补充**：右下角固定显示一个 16×16 的可见抓手（3×3 点阵，`TextDisabledBrush` 色），作为「这里可以拖」的视觉提示；鼠标 hover 时提升到 `TextSecondaryBrush`。

---

#### P0-4 月历为绝对主体（新布局）

**需求**：面板布局重做，月历占可视面积 **≥ 78%**（日程收起态）。

**验收标准**：
1. 默认尺寸 420×620 下，月历网格（含星期头）高度占比 ≥ 78%
2. 日期格子默认档尺寸 ≥ 56×80（DIP），日期数字字号 18px
3. 6 行 × 7 列网格在任何合法尺寸下都完整可见，**不出现第 6 行被裁切**
4. 现有做得好的部分**必须保留**（见 00 文档 §5）：今日高亮、非当月灰显、农历显示、圆角窗口、`ClipToBounds`、深/浅主题跟随

---

#### P0-5 农历 / 节气 / 节假日 / 调休 显示

**需求**：日期格子内以**三级信息层次**显示日期信息，法定节假日与调休上班日必须有强视觉标记。

**单元格显示优先级**（同一行文字只显示优先级最高的一项）：

```
① 法定节假日名（如「国庆节」「春节」） → 红色 #D13438(Light) / #FF99A4(Dark)
② 二十四节气（如「白露」「冬至」）      → 绿色 #107C10(Light) / #6CCB5F(Dark)
③ 农历节日（元宵/七夕/重阳/端午/中秋…）→ 橙色 #C75B12(Light) / #FFA94D(Dark)
④ 农历日名（初一显示月名如「八月」，其余「初七」「廿三」）→ 灰色 TextSecondary
```

**休 / 班 标记（本次改造核心信息）**：

| 状态 | 触发条件 | 视觉表现 |
|---|---|---|
| **休** | 该日是法定放假日 | 格子整块铺浅暖底（Light `#FFF4E5` / Dark `#3A2E22`）+ 圆角 6 + 右下角「休」胶囊（底色 `#E8A33D`，白字） |
| **班** | 该日是调休上班日（周末上班） | 格子整块铺浅蓝灰底（Light `#EAF2FA` / Dark `#22303C`）+ 圆角 6 + 右下角「班」胶囊（底色 `#5B7C99`，白字） |
| 普通工作日 | 其余 | 透明底 |
| 今天 | 与上述叠加 | 日期数字后加 30×30 强调色圆底（白字），叠加标记不清除 |
| 选中日 | 与上述叠加 | 1.5px 强调色描边（圆角 6） |

**验收标准**：
1. 有法定节假日的日期，格子内**必定**同时出现节日名与「休」标记
2. 有调休上班的日期，格子内**必定**出现「班」标记，且**不得**显示为休息日样式
3. 二十四节气在对应日期显示，全年 24 个节气**全部**能显示（逐个核对，误差 ≤ 1 天）
4. 农历闰月正确显示「闰X月」；春节至除夕的日期映射正确
5. **宁缺勿错**：若无法从数据源可靠判定某日是「休」还是「班」，则**只显示节日名、不打标记**，绝不猜测
6. 双主题下所有新增颜色对比度满足 WCAG AA（正文 ≥ 4.5:1）

#### P0-6 节假日数据来自 ICS 订阅

**需求**：法定节假日 / 放假安排 / 调休 **全部从用户订阅的 ICS 链接获取**，支持多订阅。**不硬编码、不联网自行抓取。**

**验收标准**：
1. 用户可在设置中添加 ≥ 1 个 ICS URL，配置别名（如「2026 国务院放假安排」）
2. ICS 中新增/修改的节假日条目，在刷新周期（默认 30 分钟）内自动反映到面板
3. 完全离线时，面板使用磁盘缓存（`%LOCALAPPDATA%\WinCal\cache`），**不阻塞**面板弹出
4. 代码中**不存在**任何写死的节假日日期表（可用 grep 验证：源码内不得出现形如 `new DateTime(2026, 10, 1)` 的节假日常量表）
5. 沿用现有 ICS 能力（`Ical.Net` 解析、内存+磁盘双层缓存、同日同标题前缀去重、全天事件三层防护），**不得回退**

**关键设计判断（务必实现）**：
> **ICS 数据流与「日程显示开关」必须解耦。**
> ICS 订阅承担两个用途：① 提供节假日/调休标记（**始终生效，受 P0-5 保护**）；② 提供日程事件（**受 P0-7 开关控制**）。
> 关闭日程显示时，**节假日标记必须仍然工作**。工程师不得因为「日程关了」就跳过 ICS 拉取。

---

#### P0-7 日程功能开关（保留不删）

**需求**：新增设置项「启用日程功能」，**默认关闭**。对应决策 1「不需要日程管理，但不要删除功能，可以加个开关」。

**验收标准**：

| 开关状态 | 面板底部行为 | 格子内事件圆点 |
|---|---|---|
| **关闭（默认）** | 折叠栏与事件列表**均不显示**，面板底部即月历底边 | 不显示 |
| **开启，日程区收起（默认态）** | 显示 28px 折叠栏「▸ 日程 (N)」 | 显示（最多 3 个，按颜色去重） |
| **开启，日程区展开** | 折叠栏「▾ 日程 (N)」+ 176px 事件列表 | 显示 |

1. 关闭开关后，面板高度自动收缩至不含日程区，不残留空白
2. **代码不得删除**：`EventListViewModel`、`EventItem`、`EventDetailWindow`、`IcsCalendarService` 等均在；仅由条件分支控制可见性
3. 开启后事件列表行为与改造前一致：彩色圆点、事件项左侧颜色条、hover 详情浮层（`ShowActivated=false` 不抢焦点）、无事件占位文案
4. 开关状态、日程区展开/收起状态均持久化
5. 展开日程区时，窗口**向上生长** 176px（右下角锚点不变）；若触到工作区顶部则改为压缩月历网格（单行不低于 60px），事件列表内部滚动

#### P0-8 数据源诚实化（消除假数据）

**需求**：`WindowsCalendarService.cs` 被 `<Compile Remove>` 排除编译、运行时反射 `Type.GetType` 找不到 → 静默降级到 `MockCalendarService`（`Random()` 生成随机事件）——**这个静默降级链路必须彻底切断**。

**验收标准**：
1. 源码中 `MockCalendarService` 的实例化**只能**由设置里一个显式开关「使用模拟数据（仅开发调试）」触发，默认关闭
2. 用户在设置里选择「系统日历」时，UI 必须在该选项旁显示明确文案，例如：
   > ⚠ 系统日历：本机环境（Win11 24H2 + ExplorerPatcher 旧式任务栏）不支持，不可用
3. 若用户已选「系统日历」且该源不可用，面板顶部显示一条可关闭的提示横幅：「当前数据源不可用：系统日历。已回退到 ICS 订阅。」
4. 任何情况下，面板中不得出现 `Random()` 生成的事件。验证方法：连续开启面板 10 次，事件集合必须完全一致（不含随机源）
5. 默认数据源改为**空日历服务（`EmptyCalendarService`）**或 ICS 订阅，**不得**默认 `SystemCalendar`

---

#### P0-9 快捷键兜底

**需求**：提供全局快捷键弹出面板，作为入口失效时的保底手段。

**验收标准**：
1. 默认 `Ctrl + Alt + C`（可在设置中修改）
2. 面板未显示时按下 → 弹出；已显示时按下 → 收起（toggle）
3. 快捷键与 `settings.json` 持久化
4. 注册失败（被占用）时，设置界面明确提示「快捷键被其他程序占用，请更换」
5. 在面板从未被时钟点击触发的机器上，快捷键是唯一入口，**必须**独立于钩子工作（不共用钩子代码路径）

#### P0-10 一致性清理（00 文档 §4 六项问题）

| # | 问题 | 验收标准 |
|---|---|---|

### 5.2 P1 — 重要

#### P1-1 当月放假速览条

在月历与日程区之间（或 Header 下方）加一行 28px 摘要条，当鼠标所在/当前月份存在放假安排时显示：

#### P1-2 日格悬停详情

鼠标悬停任意日期格子 400ms，弹出轻量信息浮层（复用 `EventDetailWindow` 的 `ShowActivated=false` 模式，不抢焦点）：

```
当日日程：3 条
```

**验收标准**：移开即消失；浮层不抢焦点（不影响用户当前窗口输入）；不超出屏幕边界。

#### P1-3 周末弱区分

周六、周日的日期数字使用略降饱和的颜色（不改变格子底色，避免与「休」标记混淆）。

**验收标准**：周末与工作日在视觉上可区分，但周末**不得**使用与法定节假日相同的底色或标记。

#### P1-6 首次启动引导

首次启动（无 `settings.json`）时，面板顶部显示一次性提示条：「已默认隐藏托盘图标。弹出面板：点任务栏时钟，或按 Ctrl+Alt+C。3 秒后自动消失 / 点此关闭。」
