## 一、用户亲自裁定（4 项）

### ★ Q1 — ICS 里「休 / 班」怎么识别？【已解决，超出预期】

**用户答复**：给出了**两个真实订阅地址**（原话）：

> 「你看原项目是填写订阅地址的，比如我订阅节假日、调休补班用的是
> `https://cdn.jsdelivr.net/npm/chinese-days/dist/holidays.ics`，
> 黄历用的是 `https://qilpmgl.github.io/MyCalendar/chinese_almanac.ics`」

**处理结果**：已真实下载并逐条解析两个源，**契约完全摸清，无任何猜测成分** ——
详见 `docs/02-ICS契约实测.md`。

**核心结论（一句话）**：
- `holidays.ics` 的 **`DESCRIPTION` 字段就是字面值 `休` / `班`**，二值零歧义，直接可用
- 还有两层冗余备份：`X-APPLE-SPECIAL-DAY`（`WORK-HOLIDAY` / `ALTERNATE-WORKDAY`）、`SUMMARY` 括号后缀
- **节气不需要本地推算** —— `almanac.ics` 的 `SUMMARY` 里有 `【小寒】` 这样的标记，
  2026/2027/2028 三年各 24 个、共 72 个，**100% 覆盖**，直接用即可

**状态**：✅ 关闭（原 PRD 里「靠关键字猜」的风险完全消除）

### ★ Q2 — 二十四节气走本地推算还是 ICS？

**用户裁定**：**也走 ICS 订阅**（原话：「也走 ICS 订阅」）

**实现契约**：从 `almanac.ics` 的 `SUMMARY` 提取正则 `【([^】]+)】`，命中即节气日。

**⚠️ 架构师必须处理的边界**：源 B 只覆盖 **2026-2028**。超出该范围时
**不显示节气、不回退到寿星公式、不报错**（遵守「宁缺勿错」）。

**状态**：✅ 关闭

**实现要求**：默认 420×620；最小尺寸 320×420；拖拽四边/四角自由缩放并持久化记忆。

### ★ Q7 — 开机自启默认是否开启？

**用户裁定**：**默认关闭 + 首启询问**（原话：「默认关闭 + 首启询问」）

**实现要求**：
- `AppSettings` 的 `AutoStart` 默认值**保持 `false`**（不改默认值，尊重用户机器）
- **首次启动时弹出一次轻量询问**（提示条或对话框）：「是否随系统启动？」，用户确认后才写入自启项
- 询问只在首次出现，询问结果（无论同意与否）持久化，**不重复打扰**
- 提示条中必须写明**兜底快捷键**（关联 Q6）

**状态**：✅ 关闭

## 二、交付总监拍定（8 项，按 PRD 建议值）

> 裁定原则：① 不拿技术细节烦用户；② 不为未确认的功能擅自扩大范围；
> ③ 一律选「更诚实、更少打扰、不确定时不做」的方向。

| # | 问题 | **裁定** | 理由 |
|---|---|---|---|
| **Q3** | 「系统日历」数据源选项怎么处理？ | **保留选项，但显式标注「本机不可用」**，选中时面板给出明确横幅 | 实测证明本机 WinRT 链路已断（`WindowsCalendarService.cs` 被排除编译，反射找不到 → 静默降级 Mock）。保留选项是为跨机器可用；**关键是绝不静默降级**（PRD G5） |
| **Q5** | 面板是否允许拖动位置？ | **不做，固定贴合任务栏右下角** | 用户只确认了「拖拽自由缩放」，未要求拖动。缩放热区与拖动热区会争抢鼠标事件，实现复杂度高而收益不明；且固定贴任务栏更符合「时钟替代品」心智。列为 P2，本次不实现 |
| **Q6** | 托盘默认隐藏后，钩子失效如何自救？ | **接受首启提示条**，条内写明快捷键 `Ctrl+Alt+C` | 无图标 + 无快捷键提示 = 「这软件坏了」的观感。首启提示条与 Q7 的询问**可合并为同一条**，减少打扰 |
| **Q8** | 默认快捷键 `Ctrl+Alt+C` 是否冲突？ | **采用 `Ctrl+Alt+C`**，注册失败时**自动降级并显式告知** | 无法代用户在实机验证占用情况。稳健做法：注册失败不静默吞掉，改为向用户提示「快捷键被占用，已改用 XXX」或提示手动改 |
| **Q9** | 周起始日默认改为周一？ | **改为周一** | 中国办公场景周一更常见，符合目标用户；PRD 建议值 |
| **Q10** | `ShowHeaderDateTime` / `TimeFormat` 死设置：实现还是删除？ | **实现，不删除** | 实现后 Header 右侧显示当前时间，把「时钟替代品」定位做实，同时消除死代码（00 文档 §4 已列此问题）。成本极低 |
| **Q11** | P1-1「当月放假速览条」是否需要？ | **保留，列为 P1** | 办公用户核心查询就是「这周哪几天上班」；数据已由 holidays.ics 提供，增量成本低 |
| **Q12** | 启用日程后，事件数据来源是否也走 ICS？ | **采用「用途」两级配置**：每条订阅标记用途（节假日 / 农历节气 / 日程），日程列表只消费「日程」用途的源 | 否则开启日程后事件列表会混进「端午(休)」等节假日条目，观感很差。**这是 PRD 核心判断「ICS 数据流与日程开关必须解耦」的落地方式** |
